## 3. M2（一脳）の実装と実走

設計・実装を三つのパケットに分けて Devin（SWE-2）へ委譲し、指揮官が差分と検証を再実行して取り込んだ。

- `brain/build.py` + `brain/policy.py`: 全規模の神経中核（N=71,618、nnz=7,882,609、c=0.0207）を組み立て、tanh 前の読出しを平均とするガウス方策として包む。状態 (v, I, s) を環境ごとに持ち回る。
- `learning/ppo_window.py`: 切り詰め窓の BPTT による PPO。窓を最小単位に、保存した開始状態から再計算して窓ごとに逆伝播する。**再計算が収集時の軌道を再現することを試験で確認**（窓内リセットを含めて logp が atol 1e-4 で一致）。

## 4. 直したもの（一晩で見つけた不具合）

| 箇所 | 症状 | 原因 |
|---|---|---|
| 姿勢配信 | 学習ループから 192 ステップで 1 枚しか届かない | 同じ身体ステップで GPU コピーを投入してから完了照会していた。read → 送信 → enqueue の順に直した |
| 配信サーバの終了 | 毎回 websockets の Traceback | ハンドラが待機したままサーバの close を観測できていなかった |
| 評価の指標 | 最大骨盤高が 4 回の評価で 4 桁一致 | リセット直後の受動的な転がりを拾っていた。最終骨盤高に替えた |
| 学習ログの統計 | 窓の最終ステップの値だけを記録 | 窓内の平均を取るよう直した |
| 方策の分散 | エントロピーが単調に落ちて床で止まる | 操作の急変の項が探索雑音そのものを罰していた。tanh(μ) で測る形に直し、標準偏差に下限 0.1 を置いた |
